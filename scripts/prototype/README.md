Python prototype of the Toronto Parking deck pipeline, 2026-09-05. The definition behind the acceptance numbers in the data section of the spec; `scripts/build-deck.ts` in `martinlaws/toronto-parking` is a port of it and must reproduce `deck-candidate.json` byte for byte (sha256 `fe31aa9a478ab285b76a0d9fc39398f2b2054a5fa552e596c83a2149208d2418`).

Run order, from this directory, with `rush.txt` (115 MB, gitignored, sha256 `fca9f04d…`) placed alongside: `python3 tp_pass1.py` (one streaming pass, ~9 s, writes `tp_pass1.json` + prints `tp_pass1.log`) → `python3 tp_select.py > tp_select.log` (selects, solves, colours, writes `deck-candidate.json`) → `python3 tp_report.py` (independent checks, rebuild determinism, sample grids) → `python3 verify_immov.py` (second BFS, immovable-piece list). `tp_selftest.py 60` checks the solver against 131 database rows, reading the 1,000-row fixture from `tests/fixtures/rush1000.txt` (the repo keeps one copy, next to the TS tests); `tp_calibrate.py` scores the real 40-card deck transcriptions.
